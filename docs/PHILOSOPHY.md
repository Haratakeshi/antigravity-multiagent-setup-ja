# 設計思想とアーキテクチャ解説 (Philosophy)

本ドキュメントでは、`antigravity-multiagent-setup-ja` がなぜこのルール体系・フック・サブエージェント構成を採っているのか、その背後にある設計思想を解説します。

---

## 1. なぜ「心がけ」ではなく「検証可能なプロトコル」なのか

LLM エージェントに「丁寧に実装してください」「バグがないかよく確認してください」と抽象的な指示を与えても、コンテキストが長くなるにつれて（Context Decay）、以下の失敗モードが必ず発生します：

1. **誤前提の無検証受容**: ユーザーの質問文や古い設計書に含まれる誤った前提（「関数 X が原因だと思う」等）を検証せずに突き進む。
2. **認知的閉鎖（Premature Closure）**: 最初に1つもっともらしい原因やファイルを見つけた瞬間に探索を打ち切り、並行して動いている別モジュールや別バージョンの存在を見落とす。
3. **テスト通過のためのプロダクション・テスト汚染**: テストが落ちたとき、アプリの真因を直す代わりにテストを `.skip` したり、実装の誤った出力をそのまま期待値にコピーして「テスト通過」と報告する。
4. **3ストライク固着（視野狭窄ループ）**: 同じ仮説のまま微修正を3回、4回と繰り返し、コードを複雑化させながら泥沼にはまる。
5. **コンテキスト汚染と逐次ループによる遅延（Context & Latency Inflation）**: テストの数百行の生ログを親スレッドに流し込んだり、上位推論モデルで1ファイルずつ `view_file` を繰り返したり、毎ステップ冗長な定型文を出力することで、トークンと待ち時間が爆発する。

本セットアップは、これら5つの構造的課題をそれぞれ独立した仕組みで解決しています。

## 2. 5つのコアメカニズム

### ① Internal-First PAC と確信度の校正 (`GEMINI.md` §0.1, §0.4)
- 順調な中間ステップの Predict（目的・予測・確信度）→ Act → Compare（照合）はモデルの内部思考（`<thought>`）で常時実行し、毎ターンの冗長な定型出力（「二重 CoT 課金」）を排除します。
- その代わり、本当に人間とエージェントの注意を集中すべき **高シグナル4地点**（①着手前の前提検証 §0.3、②予測と異なる結果が出たサプライズ瞬間 §0.2、③不可逆操作の Human Gate §2.2、④証拠つき完了前セルフレビュー §0.5）でのみ可視出力を義務づけます。
- 確信度は主観ではなく**証拠の出自**で上限を決めます（学習知識のみの API・CLI・モデル名は確信度50%未満＝使用前の Grounding 必須）。

### ② 機械的ガードレールとスマート素通し (`agy-harness` Lifecycle Hooks)
プロンプトのルールは忘却されることがありますが、`hooks.json` によるプロセス外スクリプトは 100% 発火します：
- **`guard_commands.py` (`PreToolUse`)**: `npm install` / `pip install` / `@latest` / `--no-verify` / `curl | sh` を実行前にブロックし、その場で `pnpm` / `uv` への最適解をエージェントに提示します。`rm` や `git reset --hard` は `force_ask` で人間の承認を必須化しつつ、`/tmp/<具体名>`（シンボリックリンク越境・ワイルドカード・ブレース展開なし）に限定した一時ファイル削除のみ安全に自動許可します。
- **`guard_file_edits.py` (`PreToolUse`)**: `/tmp/<具体名>` 以外のファイル削除確認に加え、テストファイルへの `.only()` / `.skip()` / `expect(true).toBe(true)` / 空 `except: pass` 混入を検知して警告します。
- **`guard_urls.py` (`PreToolUse`)**: `localhost` / `[::1]` 等のローカル開発サーバーと公式ドメインを素通ししつつ、`urlsplit` により `?`・`#`・`userinfo@`・`\` 偽装を含む未知ドメインアクセスを確認へ回します。
- **`session_context.py` (`PreInvocation`)**: 会話開始時と40回の呼び出しごとに今日の日付と1行リマインドを公式 `systemMessage` 形式で軽量注入し、長時間の会話でも規律の風化を防ぎます。
- **`stop_selfreview.py` (`Stop`)**: 実ファイル変更を伴うターンで完了マーカー（`GOAL_COMPLETE` 等）が欠落しているとき、または未追跡バイナリが30件以上放置されているときのみ引き止め、質問応答・調査のみの会話や既にセルフレビュー済みの応答は追加レイテンシゼロで即座に `allow` 素通しします。

### ③ 段階的合意と反証を組み込んだ 9ステップ `grill-me` / `grilling`
曖昧な要件に対して「1問聞いては少し調べ、また思いつきで聞く」場当たり的インタビューや、ゴール未合意のままいきなり関数レベルの TODO リストを作るアンチパターンを排し、3段階の Ask（②ゴール合意 → ④基本方針［**1項目1Ask・複数セクション混同禁止**］ → ⑦詳細TODO［**1項目1Ask**］）と2回の反証レビュー（⑥調査結果の反証・⑧計画の反証）を構造化しています。

### ④ 脱中心化（Mindfulness）と Tier 0〜3 リスク比例クリーンルーム監査 (`multi-agent-kit`)
- **3ストライク時の脱中心化**: 3回連続で壁にはじかれたら、まず `mindfulness` スキルで評価語を一切禁じた純粋事実（Facts）だけを観察させ、選択的注意（思い込み）を解除します。それでも打開できなければ `ask-opus`（不在時は `senior-architect-advisor`）または `multi-agent-opinion`（モードB）で別アプローチを導出します。
- **クリーンルーム原則 (§3.4)**: レビュアーには「作成者の苦労話や言い訳」を一切渡さず、純粋な **Git 差分 ＋ 不変条件仕様（Invariants Spec）** のみを渡します。
- **リスク・速度比例の Tier 0〜3 スケーリング (§3.5)**:
  - **Tier 0（日常既定）**: 軽微〜通常の実装変更はメイン自身の差分・テスト確認（`§0.5` セルフレビュー）のみで即時完了し、サブエージェント起動待ちを発生させません。
  - **Tier 1（中規模・明示依頼）**: 中規模以上の変更は高速な `second-opinion-lite`（1ターン5〜15ファイル並列読取）、重要な状態遷移・視覚検証は `carbon-verifier`（12往復上限）で迅速に監査。
  - **Tier 2（重要ロジック変更）**: 15体の専門カタログから変更領域に直結する **3〜6体を選抜** して並列走査し、Stage 2 で事実照合（ハルシネーション指摘の棄却）と複合監査を実施。
  - **Tier 3（リリース前・3ストライク Mode B）**: 単一責任15体 × 複眼3体のフルパイプラインを起動し、死角ゼロで徹底検証します。

### ⑤ 損益分岐点オーケストレーションとレイテンシ最適化 (`claude-orchestrator-kit`)
- `Gemini 4 Carbon` のような最上位推論モデルは1手あたりの固定 TTFT（7〜20秒超）が大きいため、審査 `0ms` で実行できる 15ファイル以内の `read_file` / `grep` や 10秒以内の単発コマンドまでサブエージェントに投げると「子起動＋親再推論」で逆に遅くなり、逆に数百行のテストログや 16ファイル以上の広域検索を親で抱えるとコンテキストが膨張します。
- そこで **損益分岐点（Break-Even）基準** と **1ターン並列ツールバッチ＆`agy_tool_safety` 高速パス規律**（素の `pnpm`/`uv` 優先、不要な `&&`/`;` 回避）を定め、局所・プロジェクト横断確認はメインが並列バッチで即決し、重いビルド・全テスト（`flash-runner`）や広域多軸調査（`flash-investigator`）のみ高速な Flash ワーカーへ逃がすことで、推論品質と体感速度の両立を実現しています。
