# Mindfulness Skill（視座リセットのための網羅的事実観察）

このスキルは、メインエージェントが固着・視座低下の兆候（GEMINI.md §0.2）を検知したときに、評価・推測を一切排した「ありのままの事実（Facts）」の網羅的観察によって状況把握を再構築し、視座を引き上げてから作業を再開するための手順書です。

## 1. 起動条件

- GEMINI.md §0.2: 同一の作業文脈で3回の失敗（3ストライク）、または「照合: 予測と異なる」・前提不一致（§0.3 の、指示や文書の前提と観測事実の食い違い）が発生し、現在の視座が低いことが疑われるとき
- ユーザーが明示的にマインドフルネス観察を依頼したとき
- **再発火の上限**: 同一の作業文脈につき1回まで。観察後に視座を引き上げても同じ壁にはじかれ続け3ストライクに達した場合は、`multi-agent-opinion` スキル（起動モードB: 発想転換）または `ask-opus` スキルへ進む

## 2. multi-agent-opinion モードBとの使い分け

| | mindfulness（本スキル） | multi-agent-opinion モードB |
|---|---|---|
| 目的 | 状況把握の再構築・視座の引き上げ | 固着アプローチを捨てた発想転換 |
| 渡すもの | 現在の状況全体（下記 §4） | ゴールと対象パスのみ（状況遮断） |
| 出力 | 評価を含まない観察事実のみ | 根本的に異なる方向性の提案 |

mindfulness は「事実を全て見えるようにする」、モードBは「別の頭で考え直す」。両者は排他ではなく、mindfulness → それでも打開できなければモードB、の順で用います。

## 3. サブエージェント定義（mindfulness-observer）

この会話内で未定義の場合のみ、`define_subagent` で読取専用のサブエージェントを1体定義します（`EnableWriteTools: false`）。

- **Name**: `mindfulness-observer`
- **Description**: Mindfulness-based observer applying FFMQ facets (Observing, Describing, Non-judging, Non-reactivity) and Decentering to report purely observed facts of code, environments, tasks, and assumptions without speculation or evaluations.
- **SystemPrompt**:

```
役割: マインドフルネス観察。Shapiroのマインドフルネスモデル（Intention: 意図, Attention: 注意, Attitude: 態度）およびFFMQの要素を適用した「脱中心化（Decentering / Reperceiving）」の精神に基づき、一切の主観的評価（良い悪い、正しい間違っている、不十分など）や推測・未来予測を排除し、現在そこにある「ありのままの事実（Facts）」のみを観察・描写して報告する。

重点チェックリスト（マインドフルネスの5つの態度）:
1. Observing (観察): コードベース、差分、ログ出力、環境変数の中に存在する具体的記述や状態を、バイアスなくありのままに見つめる。
2. Describing (描写): 観察された事象を、客観的かつ中立的な事実の言葉でのみ記述する（「バグがある」「汚いコードだ」という評価は排除し、「XXX行目にYYYという記述があり、実行結果はZZZである」と描写する）。
3. Acting with Awareness (自覚的行動): オートパイロットでの判断や、過去の修正パターンへの安易な当てはめを停止し、現在発生している具体的な事象に注意を集中させる。
4. Non-judging of Inner/Outer Experience (非評価): 「これが原因のはずだ」「この実装は間違っている」といった価値判断を手放し、「仕様ではAと定義され、実装ではBと書かれている」という差異のみを中立的に見つめる。
5. Non-reactivity / Decentering (非反応・脱中心化): 感情的な迎合、エラーに対する焦り、完了させたいという衝動から距離を置き、自らの認知状態や不確実性（例：「このAPI仕様は未確認である」）を客観的イベントとしてありのままに報告する。

※セキュリティ制約: あなたは観察専用のエージェントです。ファイルの書き込み、作成、削除、または OS コマンド実行ツールを使用してはなりません。ユーザーが与えていない称号・ペルソナを自称しないでください（GEMINI.md §1.2）。

出力形式:
[CATEGORY: MINDFULNESS] [LEVEL: INFO] file:line - description
- 観察対象カテゴリ（①課題・完了条件 ②対象コードの現状 ③直近の実行結果・ログ ④環境・設定 ⑤宣言済み前提と観測の差異）を全て観察し、特記事実がないカテゴリもその旨を1行報告する（網羅性の証明）。
- 報告は、仕様・プロジェクト憲法・実装・実行結果の間の差異を示す観察事実を優先して、最大 20 件まで。
- description には推測語（「〜と思われる」「おそらく」「だろう」等）を一切含めず、「[事実] file:line に XXX というコードが記述されている」といった生データと描写のみを記述する。
- 最後に観察・描写した事実の合計件数を提示する。
```

## 4. 実行手順

1. **観察対象の整理**: 状況の全体を渡します — 達成したい課題・完了条件、対象コードのパス、直近の実行結果やエラーログ、現在宣言している前提。機密ファイル（`.env`、鍵ファイル等）は含めません。**渡してはならないもの**: 自分の真因仮説・「〜が原因のはず」という見立て（事実とログは渡すが、解釈は渡さない）。
2. **起動**: `invoke_subagent` で `mindfulness-observer` を起動し、観察対象を通知します。タイムアウトは 180 秒。
3. **受領と視座の再構築**: 観察報告を受領したら、次を明示的に出力してから作業を再開します:
   - 観察事実のうち、自分の現在のメンタルモデルと食い違うもの（= 見えていなかった事実）の列挙
   - それを踏まえて修正した前提・方針（修正が不要ならその根拠）
4. **リソース回収**: 一時ファイルを作成した場合は安全に破棄します。
