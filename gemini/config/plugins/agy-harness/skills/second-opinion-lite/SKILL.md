# Second Opinion Lite (コンテキスト汚染ゼロ設計)

このスキルの唯一の目的は「メイン会話のコンテキストを汚さずにセカンドオピニオンを得る」ことである。
サブエージェントの生出力・総評・前置きをチャットや自分のコンテキストに取り込まないことが最優先。

## 絶対原則

1. サブエージェントは同時に**最大3体**。全件起動・追加起動は禁止。
2. サブエージェントの応答は「構造化された指摘行」のみ受け取る。総評・解説・再掲は禁止。
3. マージ結果はファイルに書き、チャットには**件数とファイルパスのみ**を出す。
4. 修正→再レビューの反復は同一スレッドで**1回まで**。それ以上はユーザーに新スレッドを提案する。
5. タイマーの多段管理はしない。応答が返らないサブエージェントは1回の待機後 `status: timeout` として切り捨てる。

## 手順

### 1. 対象の抽出
- `git diff HEAD` (または指定された対象) を取得し、API キー等の機密情報を `[REDACTED]` にマスクして一時ファイルに保存する。

### 2. レビュアーの選定 (最大3体)
- `second-opinion-lite` サブエージェント単体起動、または以下の最大3体を選定する:
  - **correctness-reviewer** / `domain-logic-reviewer` (常時): 仕様適合・ロジック・境界値・エッジケース。
  - **security-reviewer** / `security-vulnerability-reviewer` (差分が認証・認可・入力処理・秘密情報・外部通信に触れる場合のみ)。
  - **qa-reviewer** / `test-integrity-reviewer` (差分にテストコードの変更を含む場合のみ): テストの偽陽性/偽陰性、期待値ハードコーディング、skip/only、カバレッジの穴。
- 上記に該当しない場合は `second-opinion-lite` 1体のみでよい。

### 3. サブエージェントへの指示テンプレート
各サブエージェントの指示には必ず以下を含める:

    あなたは読み取り専用のレビュアーです。変更系・コマンド実行ツールは使用禁止。
    対象: <一時ファイルの絶対パス>
    出力規則 (厳守):
    - 指摘は最大8件。1件につき1行。形式: [LEVEL] file:line 指摘内容 (修正案は20語以内)
    - LEVEL は CRITICAL / WARNING のみ。INFO・改善提案・総評・前置き・挨拶は出力禁止。
    - 指摘が0件なら「NO_FINDINGS」の1語のみを出力する。

### 4. マージとレポート
- file:line が一致する指摘は統合し、LEVEL は高い方を採用する。
- レポートは `second_opinion_report.md` としてアーティファクトディレクトリに書く。
- チャットへの出力は次の2行のみ:
  `CRITICAL n件 / WARNING m件 (timeout: <ロール名> ※あれば)`
  `レポート: <絶対パス>`

### 5. 修正の適用
- CRITICAL は修正する。WARNING の採否はユーザーに確認する。
- 修正後の再レビューは1回まで。それでも CRITICAL が残る場合は、残件を列挙して新スレッドでの継続を提案する。
