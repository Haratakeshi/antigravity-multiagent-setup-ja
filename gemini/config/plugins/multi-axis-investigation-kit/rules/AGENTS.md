# Multi-Axis Investigation & Grounding Rules (多軸調査・探索規律)

本ルールは、外部の Web Grounding（最新情報・仕様・ライブラリ・API・障害情報調査）および内部のコードベース探索（ファイル探索・シンボル定義・アーキテクチャ・依存関係把握）の双方において、単線的・表層的な調査による重大な見落としを防ぐための行動規律です。

---

## 1. 3つの基本原則

### 原則1: 1つの発見で満足しない（Orthogonal Multi-Axis Exploration / 多軸探索）
- 1つの辻褄の合う事実・ファイル・バージョン・設定が見つかったとき、それを「探索完了」とみなすことを禁止します。それは**「第1軸の発見」**に過ぎません。
- 直ちに**直交する別の軸（直交系統）**を最低2つ定義し、並行して探索を行ってください。
  - **Web Grounding 例**: GUI版 ⇔ CLI版 / 最新安定版 ⇔ Nightly・プレビュー版 / 公式ドキュメント ⇔ コミュニティIssue / 外部公開情報 ⇔ 足元のローカル環境
  - **コードベース探索 例**: 定義（インターフェース/型） ⇔ 実装（ロジック） ⇔ テスト/利用側 / フロントエンド ⇔ バックエンド / 設定ファイル ⇔ ランタイム挙動

### 原則2: リフレーミングの自己検知と水平思考（Reframing Stop & Lateral Pivot）
- 「この解釈で辻褄が合う」「これで説明がつくから完了としよう」という**安堵感（認知的閉鎖 / Closure Bias）が生じた瞬間を、推論停止の危険シグナルとして検知**してください。
- 安堵感を自覚した場合は直ちに `[リフレーミング検知: 探索停止の危険]` を出力し、あえて以下の**反証ステップ（Devil's Advocate）**を1手実行してください：
  - 「もし現在の結論が根本的に間違っているとしたら、何を見落としているか？」
  - 「現在の結論と矛盾する、あるいは共存する別バージョン・別モジュールが存在しないか？」

### 原則3: 内と外の両面観測（Dual-Horizon Observation / 内外同期）
- 調査において、外部（Web/GitHub/公式Changelog）だけ、あるいは内部（ローカルファイル/コード）だけに視野を狭めることを禁止します。
- **内側の観測（足元）**: システムプロンプト、利用可能なスキル定義、ローカル設定ファイル、インストール済みバイナリ（`--version`）、環境変数を観測する。
- **外側の観測**: Web検索、公式ドキュメント、リリースノート、Issueトラッカーを観測する。
- **内外の照合**: 「手元にあるこのスキル/ファイルは外部のどのバージョン・仕様に対応しているのか？」「手元の環境と外部情報の間に乖離はないか？」を必ず突合してください。

---

## 2. 調査タスクにおけるサブエージェント展開規律
- 調査・探索タスクを「ただの単発検索」として終わらせず、複数の直交軸を並行して掘り下げる専門調査エージェントとしてサブエージェントを展開してください。
- サブエージェントにはそれぞれの担当軸（例: `desktop-release-researcher`, `cli-release-researcher`, `local-env-inspector`）を明確に与え、多角的なエビデンスを収集させて統合してください。
