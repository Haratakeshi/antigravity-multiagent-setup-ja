# Multi-Axis Investigation & Grounding Rules (多軸調査・探索規律)

Web Grounding（最新仕様・API・障害調査）およびコードベース探索における単線的な見落としを防ぐ行動規律です。

## 1. 3つの基本原則

1. **1つの発見で満足しない（直交多軸探索）**:
   最初の辻褄の合う発見は「第1軸」に過ぎません。直ちに直交する別軸を最低2つ定義して並行探索します。
   - **Web例**: GUI版 ⇔ CLI版 / 安定版 ⇔ Nightly・Preview / 公式文書 ⇔ Issue / 外部情報 ⇔ ローカル環境
   - **コード例**: 型定義・契約 ⇔ 実装 ⇔ テスト・利用側 / FE ⇔ BE / 設定ファイル ⇔ 実行時挙動
2. **リフレーミング自己検知と水平思考**:
   「これで説明がつく」という安堵感（Closure Bias）が生じた瞬間に `[リフレーミング検知: 探索停止の危険]` を出力し、「この結論が誤りなら何を見落としているか？」「別バージョン・別モジュールが共存しないか？」を1手反証します。
3. **内と外の両面観測（Dual-Horizon）**:
   内側（プロンプト・スキル定義・ローカル設定・`--version`・環境変数）と外側（公式ドキュメント・Changelog・Issue）の双方を観測し、手元環境と外部仕様の乖離を突合します。

## 2. 並列展開規律
- 4ファイル以上または独立複数軸の調査では、単発検索で終わらせず担当軸を明示した `flash-investigator`（または `research` に `Model: "flash"`）を並列起動してエビデンスを統合します（3ファイル以内の局所確認はメインが直接実行）。
